Smart Supply Pro – Backend API (1.0.0)

Download OpenAPI specification:

URL: https://github.com/Keglev/inventory-service License: MIT

Enterprise REST API for Smart Supply Pro inventory and supplier management system.

Features

  • OAuth2 authentication with Google
  • Inventory item management with audit trail
  • Supplier relationship management
  • Stock movement tracking and analytics
  • Real-time dashboard KPIs

Authentication

All endpoints (except health checks) require OAuth2 authentication via Google. The API uses JWT tokens managed through secure HTTP-only cookies.

Delete inventory item (soft delete)

Soft-deletes an inventory item: the row is marked inactive, never physically removed. Stock history is retained for auditing; no history row is written by the delete itself. The item's SKU remains reserved by the unique constraint.

Authorization:

  • Requires ROLE_ADMIN
  • Blocked in demo mode (APP_DEMO_READONLY=true) - returns 403 Forbidden

Business rule: the item must have quantity = 0. Remove remaining stock via quantity adjustments first; otherwise the request fails with 409.

Search inventory items

Server-side search over ACTIVE inventory items with pagination and sorting. All filters are optional: an empty name matches all active items. Sorting is fully honored via the sort parameter (no hardcoded ordering); the server-computed totalValue field is not sortable. A sort property that is not a property of the item (nested paths such as supplier.name are) is answered with 400.

Security: Requires authentication OR demo mode enabled (APP_DEMO_READONLY=true permits unauthenticated read access).

Authorizations:
oauth2None
query Parameters
name
string
Default: ""
Example: name=widget

Case-insensitive name substring; empty or absent matches all active items

supplierId
string
Example: supplierId=supplier-123

Restrict results to a single supplier

belowMinimumOnly
boolean
Default: false

When true, return only items whose quantity is below their minimum quantity

page
integer <int32> >= 0
Default: 0

Page number (0-indexed)

size
integer <int32> [ 1 .. 100 ]
Default: 20
Example: size=20

Number of items per page

sort
string
Example: sort=price,desc

Sort criteria in format: property,direction. Multiple sort criteria can be specified.

Examples:

  • name,asc - Sort by name ascending
  • price,desc - Sort by price descending
  • createdAt,desc - Sort by creation date descending

Adjust inventory quantity

Adjusts the quantity of an inventory item by a delta amount.

Authorization:

  • Requires ROLE_USER or ROLE_ADMIN
  • Blocked in demo mode (APP_DEMO_READONLY=true) - returns 403 Forbidden

Delta Logic:

  • Positive delta: Add stock (e.g., +50 to increase by 50 units)
  • Negative delta: Remove stock (e.g., -25 to decrease by 25 units)

Audit Trail:

  • All quantity changes are logged in stock history
  • Reason parameter is required for compliance tracking

Analytics

Dashboard KPIs and analytics

Get stock value over time

Returns the closing inventory value as change points: the first day in the range with stock history, every day whose closing value differs from the previous point, and the end date. The value of a day is the sum over items of the quantity held at the end of the day times the item's last known unit price, and it holds until the next point, so a step line through the points shows every day. Days before the first stock movement are left out rather than sent as 0. Quantities come from each item's whole stock history, not only from movements inside the range. An empty array means no item has any history up to end. Optional supplier filter.

Health checks and system information

Application and database health check

Reports application liveness plus a live database ping in one flat JSON body (only the databaseProduct name is cached after the first successful ping). Returns 200 when the database is reachable and 503 when it is down (the body shape is identical in both cases). Used by the container health check and by the release checks against https://api.smartsupplypro.de.

Security: publicly accessible (no authentication required).

Deep Database Health Check

Opens a fresh connection and runs an Oracle-specific SYS_CONTEXT query. Returns 200 when the query succeeds and 503 when the database is unreachable, paused (common in Oracle Free Tier) or misconfigured.

Security: publicly accessible (no authentication required), because it is the troubleshooting aid for the moments when login is impossible: login stores the user in this same database. Anonymous callers and non-admin users receive status only. An authenticated ADMIN also receives oracleSeesIp, the address the database sees for this service. A failure never reveals its cause; the exception is written to the server log.
